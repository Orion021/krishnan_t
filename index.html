Pedagogy

How I teach

I teach in a loop of measuring, teaching and measuring again. Every test is written for a specific level of Bloom's Taxonomy, so the results show not just how much a cohort knows but what kind of knowing it is.

Step 1 Baseline Assessment
Step 2 Formative Tests in Course
Step 3 Summative Outcome Test
Cognitive Model Bloom's Taxonomy Levels
Cycle Improve After Each Cohort

Start from what the cohort already knows

Before teaching a topic, I run a baseline assessment. It tells me where to start, what to skip and where to slow down, so I teach the cohort in front of me and not an imaginary average class.

Check understanding while teaching

I run formative tests during the course. They are written to reach different cognitive levels, from remembering and understanding up to applying and analysing, so I can see where learning stalls while there is still time to fix it.

Measure the final outcome

A summative test at the end shows what the cohort can do after the course. I read it against the baseline to see how far they moved.

Improve the method every cycle

After each cohort I change what the results say needs changing: the order of topics, the explanations, the questions and the supporting material.

Supporting material that fits the subject

I write PDF notes, but they are one part. What else I provide depends on the nature of the subject, because a programming language, a data science workflow and a networking topic are not learned the same way.

AI Workflow

How I use Gen AI

Core Rule

I use Generative AI across my whole teaching cycle. The rule is simple: AI creates the first version, then I review it, correct it and test it before it reaches a student.

Designing assessments

I plan each test as a blueprint by topic and Bloom's level, then use AI to draft baseline, formative and summative questions to fill it. Common misconceptions become the wrong options, so a wrong answer tells me what a student believes. I also make parallel versions so batches never see the same paper.

Preparing material

I ask for several ways to explain a hard concept and keep the one that fits my cohort. Worked examples of rising difficulty, broken-code exercises and revision sheets are drafted with AI, and the format changes with the subject.

Marking and feedback

AI helps me write rubrics so marking stays consistent, and drafts feedback from rubric scores that I personalise. For exercises, I build hint ladders: a nudge first, then a bigger hint, then the worked solution.

Reading the results

I compare baseline and summative results, look for the question types a cohort struggles with, and use that to change the next cycle's order, explanations and questions.

Building InViolate

I use AI for boilerplate, test cases and code review. Anything that protects exam integrity gets my own line-by-line review.

When I started work as a trainer, I took that habit into the classroom. It's why I care about learning that can be checked, not just delivered.

Teaching naturally turned me into a builder. Whenever I encountered a roadblock in how I taught or ran a classroom, I built a tool to solve it. I enjoy tackling challenges from end to end—starting with where students get stuck and ending with clear data on what they've mastered.
